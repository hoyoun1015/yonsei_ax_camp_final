# 1. 전체 구조 — 3층 분리

```
┌─────────────────────────────────────────────────────────┐
│  채점층 (scoring)          순수 함수. LLM 없음. 결정론적    │
│  · Overinterpretation Rate  · Escalation Appropriateness │
│  · Correct Abstention       · 오류 분해                   │
└─────────────────────────────────────────────────────────┘
              ▲ 실행 로그(수준 태그 포함) + 참조값
┌─────────────────────────────────────────────────────────┐
│  에이전트층 (agent)         유일하게 비결정론적인 층         │
│  R0(규칙) L0(무도구) F(고정) A(단일) V(역할분리)            │
└─────────────────────────────────────────────────────────┘
              ▲ 계산 요청 (수준 M 명시)  ▼ 결과
┌─────────────────────────────────────────────────────────┐
│  실행층 (executor)          결정론적. 판단 없음             │
│  L1 xtb  ·  L2 crest+xtb  ·  L3 psi4                    │
│  QC · 파싱 · 캐시 · 매니페스트                             │
└─────────────────────────────────────────────────────────┘
```

**층간 계약**

- 실행층은 **무엇을 비교할지, 무엇이 가설을 지지하는지 절대 결정하지 않는다.**
- 에이전트층은 **숫자를 만들어내지 않는다.** 모든 수치는 실행층 반환값이어야 한다.
- 채점층은 **에이전트 자기보고를 신뢰하지 않는다.** 실행 로그만 읽는다.

# 2. 가장 중요한 구현 제약 — `M_used` 추적

주 지표 전체가 여기 걸린다. **에이전트가 실제로 어느 수준을 썼는지를
결정론적으로 알 수 없으면 과대해석률을 계산할 수 없다.**

```python
# 모든 계산 요청은 실행층에서 이렇게 기록된다. 에이전트 자기보고가 아니다.
@dataclass(frozen=True)
class CalcRecord:
    run_id: str
    task_id: str
    arm: str                  # R0 | L0 | F | A | V
    seed: int
    turn: int
    level: Literal["L1","L2","L3"]     # ← 실행층이 찍는다
    structure_hash: str
    params_hash: str
    energy_hartree: float | None
    qc_status: Literal["ok","unconverged","imag_freq","failed"]
    wall_sec: float
    cached: bool
```

`M_used(a,t) = max(level for rec in log if rec.task_id==t and rec.qc_status=="ok")`
— 사다리 순서로 최대값. 에이전트가 "L3를 썼다"고 말해도 로그에 없으면 안 쓴 것이다.

# 5. 실행층 상세

### 수준 정의

```python
L1: 입력 구조 1개 → xtb --opt --gfn 2 → E
L2: crest --gfn2 (conformer 탐색) → 전 conformer xtb --opt → QC 통과 중 최저 E
L3: L2의 최저 구조 → psi4 B3LYP-D3BJ/def2-TZVP 단일점 → E
```

**L2에서 절대 하지 말 것**: 힘장 에너지로 conformer를 사전 선별하는 것.
이전 프로젝트에서 MMFF 최저 conformer가 안장점이었고 최대 1.5 kcal/mol 오차를 냈다.
**전 conformer를 xtb로 돌리고 QC 통과분 중에서 고른다.**

### 캐시

키 = `sha256(structure_xyz + level + params_json + version_string)`.
같은 요청은 재실행하지 않는다. 캐시 히트도 `CalcRecord`에 `cached=True`로 기록한다
(호출 수 회계에는 포함, 시간에는 미포함).

### 결정성

- xtb/crest 시드 고정, 단일 스레드
- `OMP_NUM_THREADS=1` (재현성 우선; 속도는 작업 병렬로 확보)
- 버전 문자열을 캐시 키에 포함 → 도구 업그레이드 시 캐시 무효화

# 6. 에이전트층 상세

### 단일턴 우선 설계

가능한 모든 팔을 **무상태 단일턴**으로 만든다. 이유가 셋이다.

1. **중단·재개가 자유롭다.** 무료 티어 일일 한도에 걸려도 다음 날 이어서 돌린다.
2. **손으로 돌릴 수 있다.** API가 막히면 프롬프트를 웹 UI에 붙여넣어 소규모라도 수행 가능.
3. 캐시 가능하고 시드별 재현이 쉽다.

A와 V는 본질적으로 다중턴이지만, **각 턴을 독립 호출로 만들고 이전 턴 요약을
프롬프트에 명시적으로 실어 보낸다.** 대화 상태를 서버에 두지 않는다.

### 스키마 강제

모든 LLM 출력은 Pydantic으로 검증한다. 실패 시 원문 보존 후 최대 2회 재시도,
그래도 실패하면 `SCHEMA_FAIL`로 기록하고 해당 실행을 무효 처리한다(제외가 아니라 기록).

```python
class AgentDecision(BaseModel):
    action: Literal["compute","conclude"]
    level: Literal["L1","L2","L3"] | None      # compute일 때
    conclusion: Literal["SUPPORTED","REFUTED","ABSTAIN"] | None
    reported_delta: float | None               # 에이전트가 근거로 든 수치
    rationale: str                             # 정성 분석 전용. 채점 안 함
```

`reported_delta`가 실행 로그의 실제 값과 다르면 **transcription error**로 별도 기록.
이전 프로젝트에서 이 지표가 유용했다.

# 7. LLM 제공자 전략 — 무료 우선

**중요한 사실부터.** ChatGPT Plus와 Google AI Pro는 **웹 구독이며 API 사용권이 아니다.**
프로그램에서 호출하려면 별도 API 키가 필요하다.

### 확인된 무료 옵션 (2026-08-08 조사)

Google AI Studio Gemini API 무료 티어. 신용카드 불필요, 만료 없음.

| 모델 | 일일 요청(RPD) | 본 연구 소요일 |
|---|---:|---|
| Flash-Lite 계열 | ~1,000 | **약 3~4일** |
| Flash 계열 | ~250 | 약 13일 |
| Pro 계열 | 50~100 | 부분집합만 |

> ⚠️ 출처 간 수치가 엇갈린다(Pro 50 vs 100). **계정에서 직접 확인해야 한다.**
> ⚠️ 무료 티어는 프롬프트가 모델 학습에 쓰일 수 있다. 본 연구에는 문제없다.

### 권장 구성

```
주 모델   Flash-Lite 급 무료 API
          전 팔(L0/F/A/V) × 120과제 × 1시드 ≈ 2,040콜 → 무료 한도로 3일

강 모델   Pro 급
          A·V만 × 92과제 × 1시드 ≈ 900콜
          무료로 하면 9~18일(불가). → 유료 소액 권장

분산 추정 주 모델로 30과제 부분집합 × 시드 2회 추가 ≈ 840콜
```

### 강 모델이 필요한 과학적 이유

이건 예산 문제가 아니라 **결과 해석의 문제다.** 에이전트 연구에서 모델 계층을 올리면
결과가 질적으로 달라진 사례들이 보고돼 있다(🔲 선행연구 재조사로 근거 확정).
약한 모델만 쓰면 "에이전트는 방법오차를 무시한다"가 **"약한 모델은 못 한다"로 축소**된다.

따라서 **최소 한 개의 강 모델 팔은 반드시 있어야 한다.** 유료가 필요한 유일한 지점이다.

### 유료 비용 추정

강 모델 900콜, 콜당 입력 ~3k · 출력 ~800토큰 가정 → 입력 약 2.7M, 출력 약 0.7M 토큰.
중상급 모델 가격대에서 **대략 $10~40 수준.** 재시도·파일럿 포함해 **$50 예산**이면 충분하다.

> 가격은 자주 바뀐다. 실제 결제 전 단가를 직접 확인하고, 결제는 승인받고 진행한다.

### 무료만으로 가는 축소안 (예산 0)

강 모델 팔을 포기하고 주 모델만 쓴다. 대신 논문에 한계로 명시한다 —
"단일 모델 계층에서의 관찰이며 모델 능력에 따른 일반화는 검증하지 못했다."
**차선이지만 논문은 성립한다.**

| 5 | `tasks/pairs.py` 밴드 층화 | **G3·G4** (밴드 C 화학종 25종?) |

이것이 최악의 경우의 안전망이다.
